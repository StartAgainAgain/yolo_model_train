# PyQt 摄像头采样设计

用户选择方案 A：在当前工程新增 PyQt 采样窗口，保留 `detect_ui.py` 的 Gradio 检测界面。范围仅包含本机摄像头选择、实时预览、一键保存图片、可持久保存的分辨率设置。

采用 PyQt5 + OpenCV + NumPy，入口 `sample_ui.py`。采样依赖使用 OpenCV headless 版，窗口由 PyQt 提供，避免其 Qt 插件冲突。不引入模型依赖，不修改现有 Python 环境。默认输出 640×480，允许 1–4096 的整数宽高，设置写入工程 `sample_settings.json`，采样 PNG 写入工程 `sample/`，路径均以脚本位置为基准。文件名使用年月日时分秒，例如 `20261105172805.png`，同一秒已有图片时提示稍后重试，避免覆盖。硬件不支持目标尺寸时，保存时缩放到设置尺寸；预览保持画面比例。

方案比较：A 新增 PyQt 采样窗口，改动集中且保留现有检测入口；B 整体迁移检测 UI，范围更大。用户确认 A。具体控件、PNG 格式、配置文件名和线程实现由实现者选择。

摄像头由 QThread 独占打开、配置、读取及释放；GUI 定时取最新帧显示，避免读取阻塞或帧信号堆积。停止和关闭只请求线程退出，线程结束后恢复控件或关闭窗口，不强制销毁仍在运行的线程。失败、停止和超过两秒的旧帧不得采样。配置损坏时使用默认值并提示；保存失败不得提示成功。

窗口含设备列表、刷新、开启/停止预览、画面区、宽高输入、保存设置、一键采样和状态提示。预览运行时禁用设备切换和刷新；停止后可重新选择。Ubuntu 按 `/dev/video*` 枚举设备，并读取系统设备名称，无设备时给出提示。文件写入和设备错误均显示在状态栏。

设备列表修正：Linux 使用 V4L2 节点能力和像素格式过滤深度、红外及元数据节点，仅保留可用于彩色采样的节点，并按 USB 物理设备路径合并。同型号、不同 USB 连接的摄像头分别保留；不可访问及虚拟设备不列出。枚举不启动流或修改格式。

验收：真实 PNG 的尺寸、颜色及唯一名称；配置恢复及坏文件处理；设备打开失败、断流和过期帧；GUI 按钮状态、后台读取、设置生效及关闭释放。当前环境无摄像头，自动测试使用设备替身和测试视频，并明确实机验证边界。
